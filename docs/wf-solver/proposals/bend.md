# `bend` — the cell where a keyed set turns a corner

The cell of a keyed cell set that holds set neighbors on both cardinal sides of one corner, reported with the corner they straddle. It is where an L turns: the two arms meet at that cell, and the corner names both the concave side and, through `diag_opposite`, the way the L points. `Bbox.corner` reports every box corner the set occupies, which an L fills three of, so it does not single this cell out.

Code form (plain relation):

```
bend(Id, P, G) :-
    cell(Id, P), diag_dirs(G, _, D, D2),
    neighbor(P, D, Q), cell(Id, Q),
    neighbor(P, D2, Q2), cell(Id, Q2).
```

Not: a cell with set neighbors on both sides of one axis (a straight run); a cell outside the set with set contact across a corner (the notch a block leaves open, `corner_only`); `Bbox.corner` (a set cell at a corner of its own box); `meet` (a position taken from two positions' components, which is an L-path's turn computed rather than found); `Rim.rim_dir` (which sides the outside lies on); a corner's two dirs read for reach, for a distance, or for a `nearer` comparison rather than for a step into the set.

Match: a rule keeping one cell of a set, with two `neighbor` atoms out of that cell whose two directions are the two cardinals of one corner — from `diag_dirs`, from two `dir_of` atoms sharing a DiagDir, or from `perp_dir` — each landing on a cell of the same set. The arm test may be written as the negation of a defect. Coarse grep: `diag_dirs`, `dir_of`, `perp_dir`.

## Spec

- **Both columns carry.** 465b7d93 keeps the corner and projects the cell away; 54dc2872's `shift` keeps the cell and drops the corner; 5ad4f10b projects both away and reads existence per key, which any keyed head gives for free. Each column has a consumer that reads it without the other.
- **One corner column, in either reading.** Two sites store the straddled corner and two store its opposite, and the crossing is one `diag_opposite` atom inside the reading site's own rule. 142ca369 reads both sides. No second readout is needed.
- **The direction column: DiagDir or Dir8.** 409aa875's `apex` is the operation with the flank relation generalized to Dir8: a corner's flanks are its two cardinals (this operation), and a cardinal's flanks are the two corners holding it. Its two glyphs read both cases in one rule, so a DiagDir-only comp serves half of `apex` and leaves the other half hand-written. Either the direction column widens to Dir8 with the flank relation stated inside the comp, or the spec records a Dir8 site as out of scope.
- **The test across the corner is the caller's, in either polarity.** 142ca369 requires the cell across the corner to be background, which is what makes its L a triomino; 5ad4f10b and 71e489b6 require that cell to be in the set, which turns the L into a 2×2 block. Callers add one atom on that cell and want opposite answers, so the comp states neither; the 2×2-block sites project the corner away and use it only to step across it, with their own `neighbor` atom.
- **The tested cell may lie outside the set.** 7666fa5d tests every grid cell against the mark set, so the comp takes the tested domain as an input beside the flank set, as `Flanked` does; a site whose tested cell is a set cell feeds the set to both.
- **The domain is a key.** The domains seen are an object id, colors, and grid-wide sets. A `Bend<Key>` with a `cell(key, p)` input serves all of them, and an unkeyed site keys on `Unit`. 142ca369's `elbow` carries a color column that is exactly that key.
- **The arm test comes free.** 142ca369, 15663ba9, and 409aa875 each write their arm test as a negation of `Rim.rim_dir` (`Rim8` at the Dir8 site). A `Bend<Key>` taking the cell set as its input states that test inside the comp, which removes those local helpers.
- **An arm readout has one consumer.** The two cells the bend's arms occupy would let 142ca369 `mark` read the L's footprint instead of stepping back out of the elbow. 54dc2872 takes the whole component and 15663ba9 reads its arm helper only inside the bend rule, so neither would call it.

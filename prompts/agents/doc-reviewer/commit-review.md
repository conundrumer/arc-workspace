# A review of a commit
- Where your brief gives a commit of `master` that the coordinator merged, review that commit's diff, with the commit before it as the commit that `contexts --diff` and `context --diff` take, and file each finding as a `bug` ticket on `commit <hash>`, with that commit's hash.
- Where your brief gives a standing doc review, first run `git tag -f <tag> <hash>`, with the tag and the commit's hash it gives. Then read the context `uv run python scripts/context.py context --at <hash> <reader> [args]` prints, from its entry point to its end, with each section that reader reaches by links, by the steps [Reviewing a change](docs/handbook/editing.md#reviewing-a-change) gives for reading a context, other than the steps that read the listing `contexts --diff` prints. The reader reaches the target of each link of that context, and of each section it reaches, where that link leads it there by the rule [Reviewing a change](docs/handbook/editing.md#reviewing-a-change) gives on when a link leads the reader to its target. Read each such section once, as `git show <hash>:<path>` prints its file. Then file each finding as a `bug` ticket on `commit <hash>`, other than one that a ticket outside `tickets/closed/` records.

# Judge pair data

[judge-brief.md](judge-brief.md) is the whole judge brief. A judge receives that brief and a directory of ordinary JSON/arclog files, reads the data with inline Python, and uses three clause commands. There are no rendered pages, viewing commands, sampling or document size limits on this path.

- [dataset-format.md](dataset-format.md) defines public tables, result files, axes and typed cells. `dataset_format.py` validates and serializes evaluator-produced TRAIN packets without implementing matching or projection.
- `export_dataset.py --pair SOURCE_PAIR --output DATA_DIRECTORY` acquires X/G through `evaluator_train.acquire_train_point` and the remaining tables through `acquire_case_train`. It accepts repeated `--pair`, persists fresh case packets once per case/program/kept/runtime/code identity, and publishes a pair atomically after metadata and tables succeed. Public `pair.json` is the entry point. Source pair manifests are execution metadata inputs, never judge documents.
- `export_by_pair_id.py PAIR_ID... [--pair-ids-file FILE] [--output DIR]` exports pairs by mechanical pair_id through `export_dataset.export_target`, with the adapter built from the corpus record by the mechanical pipeline's metadata producer. It skips DET pairs, continues past a failed pair, and prints one JSON line per pair (status, seconds, new and cached cases) and a progress line on stderr. Run it with the study runtime's Python. With `--features [--points DIR]` it writes only what the features study reads: per branch point (task, case, point), one directory under `--points` with G, the available tables, `train.json`, `gold.arclog` and `libraries.json`, and per pair only X, `mutant.arclog` and a `pair.json` whose `point` is the relative path of that directory. It computes no other target, comparison or reader file.
- `../judgetool/judge_tool.py --pair DATASET run|check|alternative --clause-file FILE --output NEW_DIRECTORY [--columns JSON_LIST]` delegates execution/checking to the shared evaluator and writes complete TRAIN `table.json` plus compact `result.json`. Private contexts, receipts and raw checked records remain below `study_paths.DATA_ROOT/judgetool`. No pass writes a grade.
- `record_data_session.py` records actual inline-Python and clause commands in order; the reader transcript contains purposes, commands and exact stdout, while stderr/status/timing stay in a separate execution record. All generated files belong under the data root.
- [nonrender-metadata.md](nonrender-metadata.md) describes the canonical source metadata provider. `case_table_metadata` authenticates source names and schemas for evaluator-returned original tables without granting read eligibility or accessing rows. Unsupported layouts raise rather than invent bindings.
- [result-records.md](result-records.md) describes the private result index and read-only `load_checked_result` resolver for the labeler. It validates source/public/private identities and forwards actual native proofs without grading or inferring judge-run completion.

The evaluator owns native replay, kept matching, equality, projection and provenance. This package owns data layout, source naming, the brief, CLI and review recording. Historical renderer modules remain code dependencies of canonical metadata extraction; the judge does not use their rendered outputs.
